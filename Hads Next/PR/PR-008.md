## Původní popis PR

HADS Next nově zvládá praktickou opravu mimo demonstrační virtuální referenci: po ověření záměru vlastníka a úplné konfigurace zapne nativní službou jednoduchou automatizaci s jediným konkrétním světlem. Immutable plán, čerstvá admin identita/CSRF, snapshot, expirace a jednorázové schválení zůstávají povinné. Funkční výsledek vyžaduje skutečný trigger, kontext světla, souvislé sledování a následné potvrzení vlastníka. Nativní stavová služba nemá CAS a konfiguraci nepřepisuje; vlastník potvrzuje výlučnou práci s cílem. Nově schválený návrat vypne jen budoucí triggery.

Přibyla omezená systémová diagnostika, persistentní epizody, disk/paměť/worker metriky, souvislost verzí, dvanáctikroková živá přejímka a anonymizovaný export. Původní Hermes, broker, CAS companion a OneDrive ochrany jsou zachovány. Opravené chyby monitorů, identifikace automatizací a pokrytí funkčního ověření jsou popsány v souhrnu.

**Ověření:** [finální běh 43278689080](https://github.com/OndraMa/HADS/actions/runs/43278689080), nativní AMD64 a ARM64, 168 regresí na každé architektuře, skutečný Core 2026.11.0 a původní Hermes, praktický plný řetězec, produkční image bez Core fixture, odmítnutí při nedostatku paměti a restart. Model byl skriptovaný a světlo virtuální. Chromium desktop/mobil: 10 pohledů. Přesný testovaný runtime `5fb55e1974e2fd25edde54d4446dcf28ea5d8933`.

**Ke stažení:** [kompletní ZIP, instalační skript, zdroje, české návody a kontrolní součty](https://github.com/OndraMa/HADS/tree/codex/hads-next-practical-acceptance/KE_STAZENI/HADS_Next_1.0.0-rc2). Obě architektury vytvořily stejný instalátor SHA-256 `e09c1d0a4b7b10775ba2e5ef238a68390316793dadb355074798e3d28e9e7a29`. Každý payload soubor odpovídá testovanému commitu; dvě sestavení celého ZIPu mají stejné bajty.

[Trvalé protokoly](https://github.com/OndraMa/HADS/tree/codex/hads-next-practical-acceptance/hads-next/docs/evidence/installation-1.0.0-rc2), [souhrn](https://github.com/OndraMa/HADS/blob/codex/hads-next-practical-acceptance/hads-next/docs/PRACTICAL_ACCEPTANCE.md), [postup bez testovacího HAOS](https://github.com/OndraMa/HADS/blob/codex/hads-next-practical-acceptance/hads-next/docs/LIVE_WITHOUT_TEST_HAOS_CS.md).

**Čeká:** skutečný HAOS/Ingress/Supervisor a MA, fyzická zařízení, Raspberry Pi a úsudek skutečného LLM. Uživatel nemá testovací HAOS; pozdější přístup do domácnosti začne pouze čtením, se zakázanými opravami a AI. Žádný produkční zásah ani placené modelové volání nebyly provedeny. Kandidát není produkčně přijatý. RC1, RC3, main a staré archivy zůstávají beze změny.
