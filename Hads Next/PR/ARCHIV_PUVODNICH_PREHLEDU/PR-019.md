## Původní popis PR

RC9 řeší překrytí záložky Domácnost v instalovaném RC8. Záhlaví a navigace sdílejí posuvný sloupec a zůstávají přístupné při zalomení identity sestavení i na nízké obrazovce.

Kandidát přidává ověření konkrétního čtení HA-MCP po připojení. Hamster zachová katalog při odmítnutí volitelného schématu a ověří omezené čtení registru. ZHA Toolkit přidává do spisu zařízení doložená registrem pro daný případ. Aktualizace z vydaných RC6 až RC8 zachovává identitu aplikace a její data.

Prošlo 326 testů na AMD64 i ARM64, ověření a spuštění stejného instalačního payloadu, kontejnerové testy Core a původního Hermesu se skriptovaným modelem a 27 lokálních kontrol prohlížeče. Živé potvrzení RC9 a Hamsteru v domácnosti, test skutečného modelu a nezávislá obnova OneDrive čekají. Přesný rozsah oprav je v matici.

RC6/RC7 uměly zobrazit přítomnost aplikací, ale chybělo provozní propojení jejich vlastních výsledků. PR spojuje stávající aplikaci a databázi se společným katalogem 15 providerů, autonomním čtecím brokerem a původním izolovaným Hermesem. Přidává konkrétní Inspector/HADocs reporty, MCP discovery/tool-search, Watchman/HAGHS/Entity Availability podklady, nativní logy/statistiky, omezená ZHA/Toolkit čtení a související konfiguraci skriptů a katalog akcí.

Samostatný vykonavatel podporuje jednu doloženou světelnou referenci přes HA-MCP a zamýšlené povolení jedné entity přes Spook. Váže providera, verzi, původ, schéma, cíl, parametry, původní stav, důkazy a ověřovatele na neměnný plán. Vyžaduje aktuální autentizovaný souhlas vlastníka, nezávislý důkaz obnovy a následnou funkční verifikaci. Nejistý zápis se neopakuje; další zápisy se zastaví, následuje omezené čtení. Návrat je samostatný plán a souhlas.

Na výslovnou žádost z 19. 11. je přiložen **instalační kandidát 1.0.0-rc8**. Stejná instalační identita a data zůstávají, ověřené RC6/RC7 se aktualizují přes Supervisor bez nové předinstalační HA/OneDrive zálohy. Ochrany skutečných oprav zůstávají. Kandidát ukazuje ověřený commit a sestavení, expiruje staré nepoužité souhlasy, má maskovanou MCP URL, konkrétní 401/403/404/503, trvalou konverzaci a patnáctiminutový collector zapojený i do incidentních důkazů a nástroje Hermesu.

Ověřený runtime zdroj: `476587fb9f7593ff951143b2f4c7c3bac011c51b`. Následné předání `c1e4f778a59032dce9aa37d266a13c98f6ddbb00` přidává pouze distribuci, dokumentaci a protokoly; 174 ověřených vstupních souborů zůstává stejných.

- **323 testů na každé architektuře ARM64/AMD64**, bez chyb a vynechání.
- Přesný instalační payload a skutečný produkční image: start bez domácí sítě, správný commit/sestavení v health, čistý SIGTERM s kódem 0. Instalátory a payloady obou architektur jsou totožné a odpovídají místní reprodukci.
- Skutečný Core 2026.11.0, pinned Inspector builder a původní NousResearch Hermes. Samostatný společný průchod Hermes → report/schema/config → inertní návrh → vlastník přes HTTP/CSRF → jeden providerový wire zápis → funkční report.
- **26 mobilních/desktopových pohledů** s anonymizovaným ingressem. Nula placených modelových volání a zásahů domácnosti.
- [Přesný běh](https://github.com/OndraMa/HADS/actions/runs/44542135579), [zachované protokoly a SHA-256](https://github.com/OndraMa/HADS/blob/codex/hads-next-orchestration/hads-next/docs/evidence/candidate-20261119/RESULTS.json).

**Meze:** model je skriptovaný; wire poskytovatelé, fyzická pozorování a hodiny jsou výslovné fixtures. Nainstalované HA-MCP/Spook/HADocs runtime, fyzické Zigbee/radio, skutečný HAOS update, reálný model a RPi prostředky nejsou živě přejaté. Všechny tři poskytnuté MCP cesty vrátily HTTP503 před initialize; veřejná cesta hlásila upstream connect error. Není tím doložená chyba HA-MCP ani ověřená autentizace/katalog.

Příjem podepsaného důkazu nezávislé OneDrive obnovy přes přesný privátní HTTPS resource je implementovaný a TLS/podpis/cíl/rozsah/stáří jsou testované. Skutečný nezávislý ověřovatel není připojený; tento consumer nevydává vlastní důkaz ani nepředstírá HABS API. HABS není povinná závislost instalace či diagnostiky HADS. Rizikové operace zůstávají bez důkazu blokované.

Obecné statistické/Recorder, registry rename/delete, script/dashboard config a Zigbee binding/reporting/channel/attribute-write adaptéry zůstávají neimplementované automatické opravy. Vzdálený Hermes worker také není implementovaný. To jsou implementační meze, nikoli pouze nepřístupný HAOS. Druhý autorský průchod a oddělené testovací kontrakty nenahrazují externí bezpečnostní audit.
